# Portfolio Generator 使用 SOP

> 将 PDF、DOCX 简历或结构化职业经历，快速转化为一套事实可信、视觉完整、可继续编辑的个人作品集网站。

## 1. 适用场景

- 求职：把简历扩展为适合面试官快速浏览的作品集。
- 个人品牌：整理代表项目、方法论与能力证据。
- 团队复用：让不同背景的使用者上传自己的简历后，自动适配内容与视觉风格。

生成过程遵循三个原则：不捏造事实、不用口号代替证据、先保证信息清晰再增加视觉表达。

## 2. 使用前准备

请准备以下内容：

1. 一份最新版简历，推荐 PDF 或 DOCX。
2. 目标岗位或目标受众，例如“AI 产品负责人”“Agent 解决方案专家”。
3. 可公开范围：哪些公司名、客户名、业务数据或项目细节需要匿名。
4. 可选信息：个人照片、联系方式、社交主页、作品链接、偏好的视觉风格。

如果简历中的项目缺少结果、个人职责或关键决策，Skill 会标记信息缺口或提出补充问题，不会自行编造。

## 3. 安装 Skill

将完整的 `portfolio-generator` 文件夹放入 Codex 的 Skills 目录：

```text
~/.codex/skills/portfolio-generator/
```

目录中应至少包含：

```text
portfolio-generator/
├── SKILL.md
├── assets/
├── references/
└── scripts/
```

安装后重新打开 Codex，或新建一个对话。输入以下指令确认是否可用：

```text
使用 $portfolio-generator，根据我接下来上传的简历生成个人作品集。
```

## 4. 标准生成流程

### 第一步：上传简历并说明目标

推荐直接使用这段提示词：

```text
使用 $portfolio-generator，根据我上传的简历生成个人作品集。
目标岗位是：[岗位名称]。
希望重点体现：[3 项核心能力]。
整体气质希望是：[克制 / 专业 / 科技感 / 编辑感等]。
以下内容不能公开：[客户名、敏感数据等]。
请严格基于我提供的事实，不要补写不存在的经历或数据。
```

### 第二步：确认内容骨架

生成网站前，建议先确认以下结构：

- 首页：姓名、当前定位、核心能力和代表项目入口。
- 项目案例：背景、问题、个人判断、方案、关键取舍、结果与复盘。
- 能力证据：把“懂 AI”“懂业务”等抽象描述落到具体行动和产出。
- 关于与联系：职业经历摘要、联系方式和外部链接。

默认选择 2–5 个最能证明目标岗位能力的项目。项目数量不是越多越好，证据密度比篇幅更重要。

### 第三步：补齐事实缺口

重点检查每个项目是否包含：

- 你面对的真实问题是什么？
- 为什么选择这个方案，而不是其他方案？
- 你本人负责和决定了什么？
- 有哪些工程、产品或商业取舍？
- 结果如何证明？如果没有量化数据，是否有可验证的定性结果？
- 哪些信息需要匿名或删除？

不知道的内容保持空缺、标记 `TBD` 或向本人确认，禁止生成虚假指标。

### 第四步：选择视觉风格

Skill 内置 10 个设计方向与 10 套配色，可组合为 100 个预设。可以直接描述审美，也可以指定预设编号。

示例：

```text
给我三个适合 AI 产品专家的预设：一个深色克制、一个编辑感、一个偏前沿科技。保持高可读性，不要大段 slogan。
```

如需本地查看全部预设，可打开生成网站的风格工作台：

```text
index.html?studio=1
```

风格选择应服务于内容，不建议同时使用过多颜色、字体或高频动画。

### 第五步：生成与预览

生成结果为静态网站目录，可直接在浏览器打开 `index.html`。重点检查：

- 首屏能否在 10 秒内说明“我是谁、擅长什么、有什么证据”。
- 项目模块是否可原地展开和收起，避免不必要的页面跳转。
- 桌面端和移动端是否都能正常阅读。
- 动效是否克制，并兼容系统的“减少动态效果”设置。
- 所有外链、联系方式与下载入口是否有效。

## 5. 发布前检查清单

- [ ] 姓名、岗位、时间线和公司信息准确。
- [ ] 所有数字、结果和职责均有事实依据。
- [ ] 客户、业务数据和内部项目已完成脱敏。
- [ ] 每个代表项目都写清个人贡献，而非只介绍团队成果。
- [ ] 页面没有未处理的 `TBD`、占位文字或失效链接。
- [ ] 首页没有空泛口号，核心能力由案例支撑。
- [ ] 手机和电脑浏览均无布局溢出或字体过小问题。
- [ ] 展开/收起、导航、下载和联系按钮可正常使用。
- [ ] 网站文件已备份，并保留一份可继续编辑的源数据。

## 6. 常用二次修改指令

### 减少文字

```text
使用 $portfolio-generator，把首页文字减少 40%。保留事实和关键信息，删除口号、重复描述与自我评价。
```

### 增强项目深度

```text
使用 $portfolio-generator，检查三个案例是否充分体现问题判断、方案取舍、个人责任和结果。不要增加未经确认的事实，缺失处列出待补问题。
```

### 更换风格但保留内容

```text
使用 $portfolio-generator，只更换视觉主题，不改动项目事实。给出三个高可读性的前沿设计预设供我比较。
```

### 面向不同岗位改版

```text
使用 $portfolio-generator，基于同一份事实材料，为 [目标岗位] 调整项目排序、首页信息层级和能力证据。不要修改原始事实。
```

## 7. 导出与交付

完成后建议同时保留：

1. 完整网站文件夹，用于继续编辑或部署。
2. ZIP 压缩包，用于传输和备份。
3. 原始简历与补充资料，但不要把含敏感信息的原文件提交到公开仓库。
4. 一份公开版内容数据，便于未来更换主题或重新生成。

静态网站可以部署到任意支持 HTML/CSS/JavaScript 的托管服务。域名购买、备案和正式发布不属于自动生成步骤，应在内容确认后单独处理。

## 8. 常见问题

### Codex 找不到 Skill

确认文件夹名称为 `portfolio-generator`，且 `SKILL.md` 位于该文件夹根目录；随后重新打开 Codex或新建对话。

### 页面好看但内容不够有说服力

先补充“问题、判断、取舍、个人贡献、结果”五类信息，再调整视觉。不要用更多动效掩盖证据不足。

### 想换风格，但不想重新整理内容

明确要求“只更换视觉主题，不修改事实内容”，并保留上一版作为对照。

### 简历中包含公司内部项目

先做匿名化：替换客户名、内部系统名、精确业务数据和未公开架构；必要时只描述问题类型、方法和个人职责。

## 9. 推荐的最短使用指令

```text
使用 $portfolio-generator，把我上传的简历转换为个人作品集网站。目标岗位是 [岗位]，重点体现 [能力 1 / 能力 2 / 能力 3]。严格基于事实，缺失信息先问我；先给内容骨架，再生成网站，并提供三个适合的视觉预设。
```

---

维护建议：每完成一个重要项目就补充一次事实材料；每次求职只调整项目排序和首页重点，不必反复重做整套网站。
